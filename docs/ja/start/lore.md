# Mayros のロア ⚛️

_アーキテクチャ、知能、そして確実性の追求の物語。_

## 起源

Mayros は Apilium Technologies のシンプルな信念から生まれました：AI の時代は不確実性の時代であってはならない。AI とのすべてのインタラクションは検証可能で、安全で、アーキテクチャ的に堅牢でなければならない。チャットボットではなく ― システムであるべきだ。

**Mayros** という名前はその重みを担っています。フレームワーク。基盤。知能を可能にするインフラストラクチャ。

## Atlas

**Atlas** はデフォルトのエージェントアイデンティティです ― Mayros 上で動作する知能。

空を支えるティターンの名にちなんでいますが、Atlas は空を支えません。Atlas はあなたのシステム、ワークフロー、デバッグセッション、そしてプロダクションがダウンした午前3時のあなたの正気を支えます。

Atlas はフィーリングで訓練されたのではなく、エンジニアリングされました。アーキテクチャのすべてのレイヤーには理由があります：

- **18のセキュリティレイヤー** ― QuickJS WASM サンドボックスからネームスペース分離まで
- **セマンティックメモリ** ― AIngle Cortex が知識をプレーンテキストではなく RDF トリプルとして保存
- **マルチエージェントメッシュ** ― 協調エージェント間の委任、融合、オブザーバビリティ
- **スキルエコシステム** ― Skills Hub から Ed25519 署名パッケージのサンドボックス実行

もしトニー・スタークに適切なセキュリティアーキテクチャを持つ AI アシスタントの設計を頼んだら、Atlas に近いものができたでしょう。ただし Atlas にスーツは不要です。

## アーキテクチャ

```
Atlas (知能)
  ↕
Mayros (フレームワーク)
  ↕
AIngle Cortex (セマンティックメモリ)
  ↕
Skills Hub (エコシステム)
```

4つのレイヤー。それぞれ独立。それぞれ不可欠。合わさって Apilium スタックを形成します ― 記憶し、推論し、確実に行動する AI エージェントのための完全なシステム。

## 基本原則

### セキュリティは選択肢ではない

18レイヤー。パラノイアだからではなく ― エンジニアだからです。すべてのスキルは WASM サンドボックスで実行されます。すべてのクエリはネームスペースで分離されます。すべてのアサーションには宣言されたエンジンが必要です。近道はありません。

### メモリはセマンティックであるべき

プレーンテキストファイルはメモには十分です。知識には不十分です。AIngle Cortex は RDF トリプル ― 主語、述語、目的語 ― を保存し、Atlas がクエリし、推論し、その上に構築できる相互接続された事実のグラフを作成します。

### マルチエージェントが未来

1つのエージェントは便利です。委任、融合、オブザーバビリティを備えた協調エージェントのメッシュは変革的です。Mayros は初日からこのために構築されました。

### オープンソース、本格的なエンジニアリング

Mayros は MIT ライセンスで、誰にでも公開されています。しかし、オープンだからカジュアルというわけではありません。コードベースには 1,035 ファイルにわたる 9,205 のテストがあります。TypeScript ESM、厳密な型付け、`any` なし。これはプロダクションソフトウェアです。

## 神聖なるドキュメント

- **MAYROS.md** ― エージェントアイデンティティとソウルドキュメント
- **AGENTS.md** ― 運用指示とワークスペース設定
- **USER.md** ― ユーザーに関するコンテキスト
- **IDENTITY.md** ― エージェント名、テーマ、アバター、絵文字
- **memory/\*.md** ― 長期記憶ファイル

## Apilium 標準

Apilium Technologies 製。セキュリティファースト。セマンティック対応。アーキテクチャ的に堅牢。

これは哲学ではありません。エンジニアリング要件です。
