# Creating Custom Skills

Mayros is designed to be easily extensible. **Skills** are the primary way to add new capabilities to your assistant — from simple prompt-only instructions to full semantic runtime hooks with sandbox execution, Ed25519 signing, and provable assertions.

## What is a Skill?

A skill is a directory containing a `SKILL.md` file (which provides instructions and tool definitions to the LLM) and optionally a `skill.ts` runtime, types, tests, and packaging metadata. Skills can be local (workspace), managed (`~/.mayros/skills`), or published to [Skills Hub](https://hub.apilium.com).

## Quick Start: Minimum Viable Skill

The simplest skill is a single `SKILL.md` file:

```bash
mkdir -p ~/.mayros/workspace/skills/hello-world
```

Create `SKILL.md`:

```markdown
---
name: hello_world
description: A simple skill that says hello.
---

# Hello World Skill

When the user asks for a greeting, use the `echo` tool to say "Hello from your custom skill!".
```

Ask your agent to "refresh skills" or restart the gateway. Mayros will discover the new directory and index the `SKILL.md`. That's it — you have a working bronze-tier skill.

## Anatomy of a Platinum Skill

Production-grade skills include up to 10 files. Each file contributes to the skill's **quality tier** score:

| File            | Purpose                                                  | Quality signal |
| --------------- | -------------------------------------------------------- | -------------- |
| `SKILL.md`      | Manifest: frontmatter metadata + LLM instructions        | Required       |
| `skill.ts`      | Runtime: lifecycle hooks (`onActivate`, `onQuery`, etc.) | Runtime        |
| `types.ts`      | TypeScript interfaces for inputs/outputs                 | Types          |
| `skill.test.ts` | Vitest tests for the runtime                             | Tests          |
| `README.md`     | Human-readable documentation                             | Docs           |
| `CHANGELOG.md`  | Version history                                          | Docs           |
| `package.json`  | NPM metadata (name, version, author)                     | Packaging      |
| `tsconfig.json` | TypeScript configuration                                 | Packaging      |
| `LICENSE`       | License file (MIT recommended)                           | License        |
| `SKILL.sig`     | Ed25519 signature (auto-generated by `hub publish`)      | Signature      |

See `skills/official/` for reference implementations with all 10 files.

## Quality Tiers

Skills Hub assigns a quality tier based on 8 signals detected in the skill directory:

| Signal    | Satisfied by                                    |
| --------- | ----------------------------------------------- |
| Manifest  | `SKILL.md` with valid frontmatter               |
| Runtime   | `skill.ts` exporting a `SkillRuntime`           |
| Types     | `types.ts` present                              |
| Tests     | `skill.test.ts` present                         |
| Docs      | `README.md` present                             |
| Changelog | `CHANGELOG.md` present                          |
| License   | `LICENSE` present                               |
| Signature | `SKILL.sig` present (generated at publish time) |

| Tier         | Signals | Badge    |
| ------------ | ------- | -------- |
| **Platinum** | >= 7    | Platinum |
| **Gold**     | >= 5    | Gold     |
| **Silver**   | >= 3    | Silver   |
| **Bronze**   | < 3     | Bronze   |

A skill with all files except `SKILL.sig` scores 7/8 = **platinum**. Publishing via `mayros hub publish` generates the signature automatically, bringing it to 8/8.

## Step-by-Step: Building with Forge

### 1. Generate your Ed25519 keypair

```bash
mayros hub keys init
```

This creates a keypair in `~/.mayros/keys/`. The public key is registered with Skills Hub when you first publish.

### 2. Scaffold a new skill

```bash
mayros forge init my-skill
```

This creates `my-skill/SKILL.md` and `my-skill/skill.ts` with sensible defaults.

### 3. Define types (`types.ts`)

Export interfaces that describe your skill's domain:

```typescript
export type Severity = "info" | "warning" | "critical";

export interface Finding {
  subject: string;
  severity: Severity;
  original: unknown;
}
```

### 4. Implement the runtime (`skill.ts`)

The runtime implements the `SkillRuntime` contract:

```typescript
import type { SkillRuntime } from "../../../extensions/semantic-skills/skill-runtime-contract.js";

const runtime: SkillRuntime = {
  name: "my-skill",

  async onActivate(ctx) {
    ctx.logger.info(`my-skill: activated for agent ${ctx.agentId}`);
  },

  async onQuery(ctx) {
    // Transform or filter ctx.results here
    return {
      results: ctx.results,
      additionalContext: "[my-skill] Enriched results",
    };
  },
};

export default runtime;
```

Available lifecycle hooks:

- **`onActivate(ctx)`** — called when the skill is loaded. Use for seeding triples or logging.
- **`onDeactivate(ctx)`** — called on unload. Reason: `session_end`, `reload`, or `unload`.
- **`onQuery(ctx)`** — called on graph queries. Filter/enrich results, add `additionalContext`.
- **`onError(ctx)`** — called on errors. Use for observability.

### 5. Write tests (`skill.test.ts`)

Use vitest with the standard `mockCtx` pattern:

```typescript
import { describe, it, expect } from "vitest";
import runtime from "./skill.js";

const mockCtx = {
  agentId: "test-agent",
  namespace: "test-ns",
  predicate: "my:predicate",
  scope: "agent" as const,
  results: [{ subject: "test:1", object: "value" }],
  logger: { info: () => {}, warn: () => {}, error: () => {} },
  graphClient: {
    createTriple: async () => {},
    listTriples: async () => [],
    patternQuery: async () => [],
    deleteTriple: async () => {},
  },
};

describe("my-skill", () => {
  it("exports a valid runtime", () => {
    expect(runtime.name).toBe("my-skill");
    expect(typeof runtime.onActivate).toBe("function");
    expect(typeof runtime.onQuery).toBe("function");
  });

  it("enriches query results", async () => {
    const result = await runtime.onQuery!(mockCtx as never);
    expect(result.additionalContext).toContain("my-skill");
  });
});
```

Run tests: `pnpm test skills/examples/my-skill/`

### 6. Document (`README.md`, `CHANGELOG.md`)

**README.md** — brief description, installation, usage:

````markdown
# my-skill

Short description of what the skill does.

## Installation

\```bash
mayros skill install @apilium/my-skill
\```

## License

MIT — see [LICENSE](./LICENSE)
````

**CHANGELOG.md** — version history:

```markdown
# Changelog

## 1.0.0 (2026-02-26)

- Initial release
```

### 7. Package metadata (`package.json`, `tsconfig.json`, `LICENSE`)

**package.json**:

```json
{
  "name": "@apilium/my-skill",
  "version": "1.0.0",
  "description": "Short description",
  "keywords": ["mayros", "semantic", "skill"],
  "license": "MIT",
  "author": "Apilium <hello@apilium.com>",
  "type": "module",
  "main": "skill.ts"
}
```

**tsconfig.json**:

```json
{
  "extends": "../../../tsconfig.json",
  "compilerOptions": {
    "strict": true,
    "module": "ESNext",
    "moduleResolution": "bundler",
    "target": "ESNext",
    "noEmit": true
  },
  "include": ["*.ts"]
}
```

**LICENSE** — use MIT (or your preferred license).

### 8. Test in sandbox

```bash
mayros forge test my-skill/
```

This loads the skill in the QuickJS WASM sandbox and runs the test suite.

### 9. Publish

```bash
mayros hub publish my-skill/
```

This:

1. Validates the manifest (`SKILL.md` frontmatter)
2. Runs the static scanner (16 rules)
3. Signs the bundle with your Ed25519 key (generates `SKILL.sig`)
4. Packages and uploads to Skills Hub

## SKILL.md Frontmatter Reference

The `SKILL.md` frontmatter defines the skill's identity and semantic permissions. For the full reference of all frontmatter keys (including `metadata.mayros`, gating, installers, etc.), see [Skills](/tools/skills).

Semantic skills use these additional keys:

```yaml
---
name: my-skill
description: What the skill does
type: semantic
user-invocable: true
semantic:
  version: 1
  permissions:
    graph: [read, write]
    proofs: [request, verify]
    memory: [recall, remember]
  assertions:
    - predicate: "my:assertion"
      requireProof: true
  queries:
    - predicate: "my:query"
      scope: agent
---
```

## Best Practices

- **Be concise** — instruct the model on _what_ to do, not how to be an AI.
- **Safety first** — if your skill uses `bash`, ensure prompts don't allow command injection from untrusted input.
- **Test locally** — use `mayros agent --message "use my new skill"` to test, or run `pnpm test` on the test file.
- **Declare permissions minimally** — only request the graph/proof/memory permissions your skill actually needs.
- **Namespace your predicates** — use prefixes like `myskill:` to avoid collisions.
